# 0045. Forms with TanStack Form and Zod 4, and report forms driven by template data

- Date: 2026-10-14
- Status: Accepted
- Deciders: Yurii Fedas
- Backlog: STACK-009 (forms and validation), touches REPORT-002 (template engine), REPORT-003 (sentinel lymph node template), REPORT-005 (report tab and editor), REPORT-006 (before-signing checklist), STACK-008 (API contract and client generation)

## Context

The web app is a React 19.3 SPA with React Compiler on ([ADR 0016](0016-react-19-spa-compiler-strictmode.md)) and compiles with TypeScript 7 under strict flags including `exactOptionalPropertyTypes` ([ADR 0006](0006-monorepo-tooling.md)). The API client is generated by Orval from FastAPI's OpenAPI 3.1 ([ADR 0017](0017-orval-api-client.md)). Most forms are small, such as login, settings, people and case filing. The hard case is the sign-out report. It follows CAP synoptic rules with ICCR elements ([ADR 0022](0022-sign-out-report-standards-and-pdf-preview.md)). Each element is core, conditional or optional, and some elements exist only when another answer says so. For example, the lymph node elements for metastasis size and extranodal extension appear only when nodes were examined and at least one holds metastasis.

Three facts shape the choice for report forms.

- Report templates are versioned data, with fields, conditional visibility, validation and computed fields (REPORT-002, template engine). The form cannot be a hand-written component per template, and the Zod schema cannot be hand-written per template either.
- The Python backend must apply the same rules, because a signed report is a legal record. The browser is a convenience and the server is the authority.
- A missing required or applicable conditional value renders as "waiting" and blocks signing (REPORT-003 and REPORT-006, before-signing checklist). Hidden fields must never leave stale values in the saved report.

Versions were checked on 2026-10-14. The spike numbers are in [results/2026-10-14-forms-spike.md](../results/2026-10-14-forms-spike.md).

## Options considered

Form libraries.

1. React Hook Form 7.90 with `@hookform/resolvers` 5.9. It is the most widely used, with uncontrolled inputs registered by `register`, and it supports React 16.8 to 19. In the spike it compiled under TypeScript 7 and React Compiler, at 13.7 KB gzip with the resolver. React's own compiler lint lists `watch()` from this library as incompatible and recommends `useWatch` ([React docs](https://react.dev/reference/eslint-plugin-react-hooks/lints/incompatible-library), [React issue 29144](https://github.com/facebook/react/issues/29144)). That puts the conditional-field pattern, which reads values during render, on a rule that developers can break by accident. In the spike the discriminated union needed a cast on `defaultValues` and an `in` check before reading an error.
2. TanStack Form 1.33. It takes Zod, Valibot and ArkType schemas directly through Standard Schema, and its examples show all three ([TanStack Form standard schema example](https://tanstack.com/form/latest/docs/framework/react/examples/standard-schema)). Form-level validators can return per-field errors, and `Subscribe` with a selector re-renders only what reads the selected value. It compiled under TypeScript 7 and React Compiler in the spike, at 18.0 KB gzip. It costs about 4 KB more than React Hook Form, its generic types are heavier, and `field.state.value` for a branch-only field typed as possibly undefined. It is the backlog default.
3. Conform 1.21. It is built around `FormData` and progressive enhancement of server-rendered forms, with a Zod adapter ([Conform](https://conform.guide)). It compiled and costs 12.1 KB gzip. The progressive enhancement that is its main strength does not apply to an authenticated, client-rendered SPA (ADR 0016), and every value arrives as a string, which the schema must parse anyway.
4. Plain controlled state with `useReducer` and a schema. It costs 0.6 KB gzip and compiled. Touched and dirty tracking, focus on the first error, async checks, draft autosave and array fields would all be written and tested by us, for every form in the product.

Schema libraries, all measured on the same schema with rolldown (minified, gzip).

1. Zod 4.6 classic, 25.0 KB. The most common, with Standard Schema support and Orval's documented zod output ([Orval Zod guide](https://orval.dev/docs/guides/zod)). The Zod docs recommend classic over Mini unless bundle size is tightly constrained ([Zod 4](https://zod.dev/v4), [Zod Mini](https://zod.dev/packages/mini)).
2. Zod Mini, 7.1 KB. The same engine with functions instead of methods, so bundlers can drop unused checks. It is more verbose.
3. Valibot 1.5, 2.5 KB. The smallest, with `variant` for unions. Orval's documentation that was found names Zod output, and whether Orval can emit Valibot output was not checked (TODO).
4. ArkType 2.2, 46.2 KB. Fast at runtime and expressive, but the largest here, and its type-string syntax is a second language for the team.

All four schema libraries and all four form approaches compiled under TypeScript 7.0.2 with the repository flags. TypeScript 7 support therefore does not separate them.

## Decision

| Concern | Choice |
|---|---|
| Form library | TanStack Form 1.x, as the backlog default suggested |
| Schema library | Zod 4 classic, imported as `zod` |
| Schemas from the API | Orval's `zod` client output for request and response bodies, after the first form task confirms that it compiles with the repository flags |
| Contract between form and schema | Forms accept any Standard Schema validator and never call Zod methods in the form layer. Swapping to Zod Mini or Valibot later touches schema files only |
| Report forms | Rendered from template data. Visibility and validation come from the template engine, not from hand-written Zod schemas |

TanStack Form wins over React Hook Form for three reasons. It takes Standard Schema directly and lets a form-level validator return per-field errors, which is the shape the template validator produces. Its `Subscribe` selector gives the conditional group one explicit place to read values, which avoids the `watch()` trap React's lint warns about. The backlog already named it. The reasons it did not win by a wide margin are real. The 4 KB size difference is small, the render-isolation benefit is an assumption that the spike did not measure (TODO in the results file), and React Hook Form is the older and more used library. Because the template validator is a pure function on a plain record, replacing the form library later would not change any rules.

Zod classic wins over Valibot on ecosystem fit, not size. Valibot is 22 KB gzip smaller. Zod classic is the format Orval documents and the one most Python-side schema tooling targets. A 25 KB cost sits next to a viewer that ships deck.gl and luma.gl. If forms ever need the bytes, the Standard Schema boundary makes Zod Mini or Valibot a contained change.

Conform loses on fit, and the reducer loses on the amount of form behaviour we would own.

## How conditional report fields are modelled, validated and sent

The worked example is the spike's sentinel lymph node template. The rules below are the decision. The spike proved them with a runnable prototype and 7 passing tests, and the real code arrives with REPORT-002 (template engine) and REPORT-005 (report tab and editor).

Model. A template is data. Each field has an id, a kind (choice, count, decimal or text), a required flag, answer options, an optional `visibleWhen` condition tree and an optional cross-field limit. A condition is a leaf (`field equals value`, `field atLeast n`) or an `all` or `any` of conditions. In the example, the metastasis size and extranodal extension fields are visible when `nodesExamined` equals `yes` and `nodesWithMetastasis` is at least 1. The reason field is visible when `nodesExamined` equals `no`. Core, conditional and optional status from CAP (ADR 0022) maps to required plus `visibleWhen`. A core element is required with no condition. A conditional element is required with a condition. An optional element is not required.

Form state. One flat record of raw strings keyed by field id. The source of each value (manual, measurement, AI confirmed) is kept beside it, not inside it (REPORT-001, report model and API, and REPORT-004, prefill from confirmed findings). The component renders the fields that the condition evaluator says are visible. A hidden field keeps its raw value in memory for the editing session, so flipping an answer back does not lose typing, but it is not validated and not saved.

Validation. One pure function, `validate(template, values)`, runs the same three steps whenever it is called.

1. Compute the visible fields from the current values.
2. For each visible field, check required, then parse by kind into a typed value with a per-kind Zod schema.
3. Check cross-field limits on the parsed values, such as nodes with metastasis not above nodes examined.

It returns either the payload or a list of field issues. TanStack Form runs it as the form-level `onChange` validator and maps the issues to fields. A draft save skips the required check. Sign-out and the before-signing checklist (REPORT-006) run it with the required check, and every visible required field with no value is a blocker that links to the field. This is the same rule that makes a value render as "waiting" in the report (REPORT-003, sentinel lymph node template). Fixed forms outside reports, such as login, use a plain Zod schema, with a discriminated union where one is needed.

Sent to the API. The request carries the template id, the template version, the typed values of visible fields only, and the source of each. Hidden fields are never sent, so a stale deposit size cannot survive a change from "examined" to "not examined". In the spike test, leftover values for hidden fields were dropped from the payload. Orval cannot express the per-template shape in OpenAPI, so the generated schema covers the envelope and a map of field ids to string, number or boolean values. The template check happens in code on both sides.

Server authority. The Python backend evaluates the same condition tree and the same rules on save and again on sign-out. It rejects a value for a hidden field with a 422 naming the field, rather than quietly dropping it, so a mismatch between the two evaluators shows up as a test failure instead of a silent data difference. A draft stays pinned to the template version it started on.

## Consequences

- REPORT-002 (template engine) must define the condition tree and field kinds as a documented data format and ship shared fixtures that both the TypeScript and Python evaluators pass. This is the largest risk of the design, because two implementations can drift. The fixtures are the control.
- The web app gets one `validate` function and a thin `TemplateForm` component. They go into a package or folder that REPORT-005 (report tab and editor) owns, tested with the cases in the spike.
- The first component that uses TanStack Form should add the dependency to `apps/web` with an exact version. No dependency was added by this decision.
- Orval's `zod` output is unverified in this repository. The first form task generates it and runs it through `pnpm typecheck`. If it fails the strict flags, hand-written Zod schemas for the few fixed forms are the fallback, and the OpenAPI types still guard the API boundary.
- Report editing components must not read values with anything that bypasses the form store, and must use a `Subscribe` selector for visibility. A component test in REPORT-005 checks that fields show and hide without losing focus, which also covers the render-isolation assumption.
- When a group hides while holding values, the editor should say that those answers will not be saved. That wording and placement belong to REPORT-005 and the design kit.
- STACK-009 (forms and validation) can be ticked once the log entry is written. The backlog lines for REPORT-002 and REPORT-005 should link this ADR.
- Open items are in the results file: a browser render and re-render check, Orval zod output, a Python evaluator on shared fixtures, and a bundle budget for forms.
