## Where we are now

Parfocal is an AI results review app since 2026-10-17 ([ADR 0053](adr/0053-ai-results-review-direction.md)): researchers import or run AI on whole slides and evaluate it, and doctors review it. [BACKLOG.md](BACKLOG.md) holds 796 tasks in 53 epics, 170 are ticked, and 89 are kept as ideas. On 2026-11-01 it was brought in line with round 6 of the POC mock: decision styles, the Display panel, submit gating, the round 6 disagreement queue, the clinical report with sign-out and co-sign, the Team view and issue states in every flow, with ADR 0131 (decision styles, raw answers and submit gating), ADR 0132 (display settings, presets and task locks), ADR 0133 (queue decisions in the task's style, left open and anonymous adjudicators) and ADR 0134 (clinical report per case with sign-out and co-sign) waiting for the owner. The review loop's backend is built end to end: result sets, object IDs, review tasks with splits and scopes, decisions, the least sure first order, the reviewed layer and its export, opinion answers, review states and moves, blinding with a kept first read without the AI ([ADR 0118](adr/0118-blinding-and-a-kept-first-read.md), proposed), the disagreement queue with decisions, sign-off, My work with next and previous slide, the evaluation metrics, Home's aggregate with announcements, the notification catalogue and the sentinel node staging rules. The security backend gained a threat model, an Origin check on cookie writes, rate limits, retention with legal holds and access and erasure workflows. What is left of M3 is mostly screens, which wait for the final UI. The ingest worker now takes a completed upload from storage through identify, scan, validate, index and derive to a published slide in its project and case, built by INGEST-017 (publish step and slide status) and waiting for a green CI run on `main`, with a polled status route as the live status ([ADR 0122](adr/0122-ingest-publishes-the-slide-row-only-when-it-is-ready.md), the slide row appears only when it is ready, proposed). The upload protocol is [ADR 0116](adr/0116-resumable-uploads-with-s3-multipart-and-uppy.md) (S3 multipart with part URLs signed by the API and Uppy in the browser), accepted on 2026-10-31 and proven against MinIO with a 4 GiB file that resumed after a cut link and a closed page. The platform is [ADR 0003](adr/0003-pilot-platform-architecture.md): Cloudflare for the web app, edge and storage, Modal for Python and GPUs, and Neon for Postgres. Work ran locally from 2026-10-08, and on 2026-10-31 the owner opened Modal, Neon and the Zitadel CI credentials again, on the condition that every cloud run costs as little as possible ([knowledge/platform.md](knowledge/platform.md)).

RSET-011 is ticked, with [ADR 0127](adr/0127-imported-cells-keep-numbers-by-centre-and-take-the-innermost-region.md) (imported cells keep their numbers by centre distance and take the innermost region, proposed). The upload API of INGEST-001 (upload API with presigned multipart) creates, signs, lists, checks, completes and aborts multipart uploads against MinIO and queues the ingest job, and waits for INGEST-028 (upload protocol check on the R2 dev bucket) ([knowledge/uploads.md](knowledge/uploads.md)). INGEST-017 (publish step and slide status) runs the steps on the uploaded file, moves it out of quarantine, writes the level table, previews and tissue mask next to it and labels and macros under a restricted prefix, and publishes the slide. `GET /api/uploads/{upload_id}/status` answers uploading, processing, ready or failed with a reason. RSET-004 (pairing results with slides) pairs dropped result files with slides through `POST /api/uploads/pairings`, lets an upload be a result paired with a slide or a slide upload, and imports it as a result set once the slide is ready, with `waiting` on the status until then ([ADR 0125](adr/0125-result-files-pair-in-python-and-import-as-their-own-job.md), result files pair in Python and import as their own job, proposed). It waits for a green CI run on `main` |
