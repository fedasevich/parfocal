Current state machine

Eight kinds of link lead to six slide routes. All six render the same component, apps/web/src/viewer/engine-viewer.tsx, which draws through apps/web/src/viewer/slide-stage.tsx, yet each route passes a different set of abilities. The workspace is picked by resolveWorkspace in apps/web/src/viewer/workspace.ts:36. A workspace named in the address wins, a review task gives the Full viewer, and everything else gives Annotate.

works through the one engine stagea second drawing path, or a dashed arrow that changes the result by entry or by the scene parameter

Roles in play. A Researcher who owns the project can do everything. A Reviewer reviews and annotates the slides of their tasks, by decision 162 (annotator and read only viewer are not roles of their own). Admin rights add workspace setup and no access to slides, so they change nothing in the viewer. The project roles owner, reviewer and viewer narrow this per project. The viewer screen reads only whether the person is the owner.

What does not make sense

Ranked by how much each one confuses a pathologist at the microscope. The line with the coloured edge says why it hurts.

  1. The same slide opens in a different viewer depending on where you clicked.

    A slide with no task opens in Annotate from the project row, from search and from My work, and in the Full viewer from the jobs tray, the upload page and the report. The default is Annotate whenever there is no review task, and one helper forces Full viewer.

    A pathologist cannot learn where a slide will land. Drawing tools appear when they only wanted to look, and drag selects in one place and pans in the other. Decision 163 (where a project slide row opens) is one case of this, and its answer should be applied through one rule.

    For a review task the code works out that the slide is assigned to others, signed off or withdrawn, and passes that only to the objects card. The Opinion form stays editable, Submit stays in the top bar and in the Opinion tab, and the rail keeps Smart select and Comment. The server refuses the save because the person has no assignment.

Proposed architecture

The core rule is short. One viewer shell on one route, where the mode comes from the task, the access comes from one function of role, assignment and task state, and everything on screen is looked up from those two values. Compare and Focus are layouts of that shell and never separate screens.

decided in one placeread only, always with a reason and a bannerlayout, free to combine with any mode

The rules that keep it simple

  1. One route and one shell. Every link to a slide is built by one helper and lands on /projects/$projectId/slides/$slideId. The other addresses redirect to it.
  2. The mode comes from the task and nothing else. No task gives Look or Annotate, a review task gives Review or Guided, an annotate task gives Annotate. The entry point never changes the mode.
  3. Access is derived once. One function takes the role, the project role, the assignment, the task state and the slide state and returns edit, or read only with one reason. The rail, the cards, the opinion form, Submit, the keys and the annotate panel all read that one value.
  4. Capabilities are data. One table maps mode and access to tabs, tools, actions and keys. A tool that cannot work in the current state is not shown, and its key does nothing.
  5. Layout is separate from mode. Single, Compare, Focus and Object are layouts of the same engine stage, so every tool and notice of the mode keeps working in them.
  6. The scene parameter belongs to the prototype gallery only and never selects a screen in production.
  7. Each mode has one progress control and one finish action, in the top bar.
  8. Notices come from one ordered list, so a slide problem reads the same in every mode and layout.
  9. The server mirrors the access rule, so the layer endpoints check the assignment the same way the opinion endpoint already does.

Migration list

In order. The first five close gaps where work is lost or a rule is skipped. The rest remove the duplicate paths. Each line can become a backlog task.

  1. Add one access function for the viewer that returns edit or read only with a reason, and unit test it against the permissions matrix.
  2. Make the Opinion form, both Submit buttons and the rail obey that access value for review tasks.
  3. Apply the same access value to annotate tasks, with a read only banner for people who are not assigned experts, and for withdrawn tasks.
  4. Add the assignment check to the annotate layer write endpoints, with a test for a member who holds the review right and no assignment.
  5. Run the first read guard inside EngineViewer so that every route gets it, and add a test that opens a blinded task through /live.
  6. Build every slide link through one helper and delete the forced workspace in viewer-links, so that one rule picks the mode. Apply the owner's answer to decision 163 (where a project slide row opens) inside that rule.
  7. Pass the role into the mode rule, so a project viewer opens in Look and is never offered Annotate.
  8. Redirect /live, /annotate and /annotate-task to the main route, and move the guided and cells routes to a mode value on it, keeping object, camera and tab in the address.
  9. Rename the workspace values so the address, the button and the code say the same word, and show the same options for the same task kind every time.
  10. Rebuild Compare as a layout of the engine stage, with the rail and tabs of the current mode, and remove the picking and picked scenes.
  11. Make Focus a layout that works in every mode, and delete the prototype FocusView branch.
  12. Take objects, travel, region, auto and models out of the live scene lists, so the prototype screens open only from the gallery.
  13. Keep one progress control and one Submit in the top bar, and turn the Opinion tab card into the form only.
  14. Draw the disagreement queue and adjudication cards with the engine stage in Object layout, and give the adjudicator a link to open the slide in Review.
  15. Turn tool keys off wherever the rail is hidden, and make the back link return to the page the person came from.
  16. Move the slide kind notices (no pixel size, remote source offline, result importing or failed, no result) into one ordered list shown in every mode and layout.

Not checked in this pass: the behaviour of the ruler on a slide without pixel size, what the guided route shows for an annotate task, and the running app itself. Every claim above comes from reading the files named.
