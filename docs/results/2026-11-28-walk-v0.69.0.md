## Question

Does the deployed clause of each of the four tasks hold on app.parfocal.eu at release v0.69.0, and what do two 11 tile runs, one outlines only and one typed, take and cost?

## Method

Throwaway Playwright scripts in the agent scratchpad ran against `https://app.parfocal.eu` with the storage state in `~/.config/parfocal/walk069-session.json`, one headless page at a time, as in the walk of v0.66.0 ([2026-11-28-walk-v0.66.0.md](2026-11-28-walk-v0.66.0.md)). They log what they measure and each task is judged from those numbers. No screenshot was opened. The active workspace was `cvut-biomedical` at the start and was left there, so the other two workspaces were not read. The sign in was repeated just before the two runs.

- PROTO-211: the estimates route was read for all 41 slides, then `/projects/{id}/run-model` and the Objects tab of the viewer were opened for CMU-1-Small-Region.svs, test_065 and CMU-1.tiff. This was done before any run.
- PROTO-207 and PROTO-210: test_065 was opened, zoomed by wheel to image point 43476, 24152 at zoom 2^1.29, Smart select armed with the Good model, which runs in the browser. The Typing switch was turned off and on again once. Then: click a cell, two Shift clicks 3 px away, three Cmd+Z, click the cell again, Enter, wait for the typing chip to end, one Cmd+Z, click 90 px to the right, Enter, wait for the chip, key 2. Saved annotations were read from `GET /api/slides/{id}/annotations` after each step. A second pass repeated only the accept and its undo: click, Enter, wait for the chip, Cmd+Z, Cmd+Z, Escape, Escape, with the boxes of the saved cell and of every proposal measured after each key.
- PROTO-212: both runs were started from the Run a model window on the one copy of CMU-1-Small-Region.svs (2220 by 2967) in "Scanner format comparison", one after the other. A route guard in the script let a `POST /model-runs` through only with that one slide id, the `pathosam-hovernext` detector and, for the first run, `typer` null. The run was polled every 4 s through `getModelRun`, and the stored cells were read from each result set's class counts and cell summary.

## GPU time and cost

Two model runs (35.3 and 40.8 GPU seconds, $0.0143 together at the estimate's rate) and three typer calls (7.86, 0.074 and 9.631 GPU seconds by the audit events, the last from the second pass at 15:26 UTC). The Good outline model ran in the browser and used no server GPU.

`modal billing report --for today` showed the `parfocal-gpu-pool` app at $1.00471486 at 15:14 UTC before the walk, $1.03018031 at about 15:19 UTC just before the runs, $1.15056615 at 15:23 UTC, one minute after the second run finished, and $1.21714528 at 15:26:48 UTC, 30 s after the last typer call. The `parfocal-api` app read $0.79148615, $1.18228882, $1.39503826 and $1.39707922. So the day's GPU bill grew by $0.2124 from 15:14 to 15:27 UTC, $0.1204 of it across the two runs. That growth is shared with every other agent that used the pool in those 13 minutes (the audit log holds another session's typer call on the same slide at 15:09 UTC), it includes cold start and idle time before the scale down, and the report may still lag. So this walk's own cost was not measured apart from the others. The two runs alone stayed under the 20 cents allowed by both figures.

## Interpretation

PROTO-212 and PROTO-207 hold on the deployed app. PROTO-211 now shows a projected figure on both screens, the same in each, because the reseed stored tissue masks, but its no-scale case is correct only in the API and not told on screen. PROTO-210 takes back live clicks one at a time and deletes the accepted cell in one press, but the outline stays drawn as a proposal. Whether that is a defect depends on what an undone accept should leave, which is a product choice. The outlines only run stores untyped cells and says why, and the typed run types every cell.
