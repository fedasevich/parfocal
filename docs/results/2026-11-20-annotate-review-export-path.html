From an uploaded slide to human reviewed training annotations

The owner asked on 2026-11-20 for one path: upload a slide, annotate it by hand, with one click tools or with whole slide models, have people review and edit the result with every edit recorded, and end with annotations for AI training. This page maps that path. It was read from the code, the ADRs and the board on 2026-11-20. Nothing was changed, nothing was measured and the deployed app was not opened. The same content as text, with the full task list, is in docs/results/2026-11-20-annotate-review-export-path.md.

The path, today and proposed

Almost every piece exists in the API. The path breaks because it is built twice, on two kinds of task that never meet. A review task has decisions and adjudication and no training export. An annotate task has recorded edits and the training export and no adjudication. The task you opened is a review task.

The green arrows are the join: both kinds of task end in one final layer and one dataset builder.

The five biggest gaps

  1. A review task cannot produce a training dataset. training_exports.py and patch_exports.py refuse any task that is not an annotate task. A doctor's corrections in a review never reach training data.
  2. A reviewer cannot edit a shape in the live viewer. apps/web/src/viewer/stage-guided-card.tsx never opens the disagree reasons and passes an empty handler to "Redraw the outline" and "Change the type". Split and merge have API routes and no caller.
  3. A review edit is not fully recorded. review_edits keeps one row per reviewer and object, a save replaces it, and the audit entry stores only the words retyped, reshaped or deleted. The AI original is safe. The steps in between are lost.
  4. Adjudication settles an answer, not a shape. disagreement_decisions has no geometry. When two reviewers redraw one region differently, the consensus export takes the earliest redraw.
  5. The dataset has no home on screen and no version. The QuPath GeoJSON zip and the patches with masks are routes with no button. There are no filters, no stored version, no model version in the manifest and no COCO.

Recommended order

  1. Buttons for what exists: the dataset zip and the patch export on an annotate task. The path is then complete for annotate tasks.
  2. Editing in the live review: the reasons card, redraw, retype, handles and brush.
  3. History for review edits.
  4. Model name and version, edit counts and filters in the export, with a stored dataset version.
  5. Shape disagreements and the adjudicator's outline.
  6. The final layer that lets a review task feed the same dataset builder.
  7. Split and merge on screen, COCO, and one end to end spec over the whole path.

Steps 1, 2 and 3 need no answer from you. The stored version in step 4 waits for question D, step 5 for question B and step 6 for question A.

Questions only you can answer

A. Which task carries training data from reviewed AI objects?

  • A. Both, joined at the end. A signed off review task becomes a final layer that the existing dataset builder reads. One export for everything, and a doctor's corrections become training data. One large task and an ADR. Recommended.
  • B. Only annotate tasks make training data. Review tasks only measure the model. Nothing to build but buttons.
  • C. Merge the two kinds into one task with a switch for independent work. Simplest to explain and the largest rewrite.

B. When two reviewers draw different outlines for one object, who settles it?

  • A. The adjudicator picks one of the outlines or draws a new one. Outlines count as different below a set overlap, changeable per task. The starting value is TODO and is picked in the task from fixture outlines. Recommended.
  • B. A rule merges them with no person, for example the area most reviewers marked. A shape nobody drew enters the data.
  • C. Shapes are not compared and the latest edit wins.

C. Which training formats come next after QuPath GeoJSON and patches with masks?

  • A. COCO JSON beside the patch tiles. Recommended.
  • B. COCO and also instance maps per tile for nucleus models in the HoVer-Net style.
  • C. Nothing more for now.

D. What is a dataset version?

  • A. A frozen copy of the manifest and the GeoJSON, stored write once with a number and a checksum. Patches are cut again from it when asked. Storage cost per version: TODO, to be measured in the task. Recommended.
  • B. A frozen copy of everything, tiles included. The largest storage use.
  • C. Only a saved recipe that is built again on demand. No storage, but a change after sign off can make the same recipe give different data.

E. Which objects go into a dataset by default?

  • A. Only objects a person checked: agreed or confirmed, edited and added. Objects answered unsure or left open are left out and counted. Recommended.
  • B. The same, plus unchecked AI objects marked ai-unchecked.
  • C. Everything, with the origin left to the researcher to filter.
